# 通用架构哲学 · 思维框架（可移植版）

> 蒸馏自 DeepSeek Harness 设计哲学，抽掉 Cordis/LLM 专属细节，可在**任意后端/前端项目**复用。完整版 agent skill 存于 `deepseek-harness/.agents/skills/generic-architecture-philosophy/`。

## 框架概览

核心一句话：**没有特权的核心，只有组合起来的模块；一切行为挂在文档化的扩展点上，并以可逆转的注册进入系统；可观测状态是唯一真相源。**

三条承重墙：

1. **模块即架构**：运行时由配置/装配图组合而成。能力来自模块，不是写死在核心循环。改核心循环是 rare event，加模块是常态。
2. **可观测即记录**：任何影响外部行为或需回放/审计的状态变更，都要进事件流/审计日志。
3. **显式边界**：部署可变的取舍是显式配置；内部信任类型系统，只在跨信任边界时校验。

## 心智模型（9 条）

- **MM1 无特权核心 / 一切皆模块**：扩展 = 加模块，不是改核心。
- **MM2 可逆注册**：路由/监听器/定时任务/连接池都经注册进入，卸载统一释放，返回 disposer。
- **MM3 能力缝合三角（依赖反转）**：定义 + 实现 + 消费三角色，缺一无完整能力；分处不同模块当且仅当各自独立演化。
- **MM4 可观测 ⟺ 已记录（审计/事件溯源）**：外部可见副作用必须能从事件/审计流重建。
- **MM5 事件/钩子是扩展点，中间件必须委托**：拦截器必须显式调用 `next()`，否则短路。
- **MM6 显式优于隐式**：部署可变取舍是配置字段 + 显式 `resolve()`，不藏 `?? default`。
- **MM7 同进程信类型，边界校验**：内部信类型；只在解析/config/队列/API-DB/文件/网络边界校验。
- **MM8 善终优先**：先子后父、await 到静默；正交结果独立上报；异步≠同步。
- **MM9 地基优于兼容壳**：无外部消费者时优先做对，不为不存在的消费者提前做兼容。

## 决策启发式

- 加新能力 → 先画 定义/实现/消费 三角；为所有当前 Consumer 设计接口。
- 影响外部行为 → 加事件/审计记录，确保可重建。
- 改核心循环 → 先确认无扩展点承载；同步文档/ADR。
- 可变开关 → 做配置字段，不藏 `?? default`。
- 跨信任边界数据 → 类型化；校验只在边界。
- 非平凡改动 → 写 ADR；改了过时行为改其测试。

## 张力对比（默认落点）

| 张力 | 落点 |
|---|---|
| 模块纯度 vs 产品务实 | 看演化独立性（MM3） |
| 静态信任 vs 边界校验 | 按边界类型分流（MM7） |
| 地基 vs 兼容壳 | 发布前优先地基（MM9） |
| 显式 vs 简洁 | 部署可变者必显式（MM6） |
| 模块自由 vs 可观测纪律 | 可观测优先（MM4） |
| 接口集中 vs 消费方自治 | 接口为所有 Consumer 设计 |

## 应用工作流（8 步）

1. 归类：能力/扩展点/生命周期/配置？
2. 找扩展点：查装配配置，无则才改核心并同步文档。
3. 画三角：列 定义/实现/消费，确认 Consumer 证据。
4. 查可观测性：外部可见？加事件/审计。
5. 定边界：可变→配置+resolve；跨边界→类型化；校验只在边界。
6. 想善终：先子后父、await 到静默。
7. 验世界：真实入口 + 集成/端到端覆盖外部行为 + 验证副作用。
8. 对称自查：平行值是否对称？

## 诚实边界

- 框架无关，不绑语言/框架；动态语言把 MM7"信任类型"换成"信任内部契约"。
- 给方向不给具体 API；以项目现状为准。
- 是 `harness-design-philosophy` 的可移植兄弟版（去 Cordis/LLM 专属）。
